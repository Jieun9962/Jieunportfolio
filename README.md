# portfolio🐇

초기 정보 구조 설계부터 UX 기획, UI 디자인, 구현까지 전 과정을 직접 수행한 프로젝트 입니다.
웹 접근성을 개발 완료 후 별도로 점검하는 항목으로 두기보다 콘텐츠 구조와 화면 구성, 마크업을 설계하는 단계부터 고려하였습니다. 실무에서 습득한 접근성 검증 관점을 실제 디자인과 개발에 반영하며 기존 역량을 점검하고 확장했습니다.

I independently handled every stage of this project from information architecture and UX planning to UI design and development.
Accessibility was part of the process from the beginning rather than a final step after development. I applied the accessibility evaluation skills I had gained through professional experience to the design and development process.
This also gave me an opportunity to revisit and build on my existing skills.

## Project Goals
- Build an accessible portfolio following WCAG guidelines WCAG 가이드 라인을 고려한 웹 접근성 포트폴리오 구축
- Demonstrate accessibility-first design principles 접근성을 우선으로 고려하는 디자인
- Provide responsive layouts across devices 다양한 기기 환경에 대응하는 반응형 레이아웃 구현
- Improve keyboard navigation and screen reader compatibility 키보드 탐색 및 스크린 리더 호환성 개선
- Create an inclusive experience for all users 모든 사용자를 고려한 포용적인 사용자 경험 제공

## Design & Development
기존 웹사이트 템플릿을 사용하지 않고, 프로젝트의 초기 기획부터 구현까지 직접 진행했습니다.
Unlike many portfolio websites built from templates, this portfolio was designed and developed entirely by me.

This includes:
- Information Architecture 정보 구조 설계
- UX Planning 사용자 관점의 콘텐츠 탐색 흐름 및 화면 구성 기획
- UI Design 인터페이스 디자인 및 시각적 요소 구성
- Custom Illustrations & Graphics 일러스트 및 그래픽 요소 직접 제작
- Responsive Web Design 다양한 화면 크기에 대응하는 반응형 레이아웃 구현
- Front-end Development HTML, CSS, JS를 활용한 웹사이트 구현
- Accessibility Testing 키보드 탐색 및 보조 기술을 활용한 접근성 점검
- Accessibility Optimization 점검 결과를 바탕으로 마크업과 인터페이스 개선

 ## Accessibility Features
 프로젝트 전반에 걸쳐 다음과 같은 접근성 요소를 고려하고 적용했습니다.
This project was developed with accessibility in mind.

Implemented features include:
- Semantic HTML structure 시멘틱 HTML을 활용한 콘텐츠 구조 구성
- Keyboard-only navigation 키보드 탐색을 고려한 인터페이스 구현
- Visible focus indicators 명확하게 식별할 수 있는 포커스 표시 제공
- Appropriate heading hierarchy 논리적인 제목 계층 구조 적용
- Alternative text for images 이미지 대체 텍스트 제공
- Color contrast following WCAG recommendations WCAG 권장 사항을 고려한 색상 대비 설계
- Responsive design 다양한 화면 크기에 대응하는 반응형 디자인
- Screen reader compatibility 스크린 리더 사용환경을 고려한 콘텐츠 및 마크업 구성
- ARIA attributes where appropriate 적절한 aria 속성 적용

## Reflection ✨

이번 업데이트는 디자인에 좀 더 개인적인 색깔을 담을 수 있는 기회였습니다. 일반적인 요소를 사용하는 대신 저만의 상징과 모티프를 중심으로 디자인을 구성했습니다. 레이아웃과 애니메이션을 최소한으로 유지하도록 의도하였으며 단순하면서도 여백의 미를 나타낼 수 있도록 하는 것이 가장 큰 과제였습니다.
개발 후 접근성을 고려하는 것이 아닌 프로젝트 초기부터 접근성을 고려하였으며 이는 앞으로 진행할 프로젝트에서도 계속 이어나가고자 합니다. 현재 iOS 기기를 사용할 수 없어 VoiceOver 테스트는 진행하지 못한 상태이지만 추후 테스트할 수 있는 여건이 된다면 다시 검토할 예정입니다.

This update was a chance to make the design feel more personal. I built around my own symbols and motifs rather than something generic. Keeping the layout and animation minimal was a deliberate choice, and getting that restraint to feel considered rather than sparse was the real challenge.
Started with accessibility from the outset, rather than layering it on at the end. It's an approach I'll take into future projects. VoiceOver testing remains outstanding as I don't currently have access to an iOS device. It's something I plan to revisit when I have the means to do so.
